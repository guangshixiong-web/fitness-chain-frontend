一张图看懂前后端协作时序

把项目中最核心的 4 条交互链路用时序图画出来：从用户打开登录页、到 Next.js SSR 鉴权布局、 再到仪表盘数据加载和 CRUD 业务操作。每条流程都配了中文注释和关键源码位置，让你能对照代码真正跑通。

1 登录认证流程

用户点"登录" → 拿到会话 Cookie → 跳转到仪表盘的完整链路

sequenceDiagram
    autonumber
    participant Browser as 用户浏览器
    participant Login as LoginView
    participant API as api.ts axios实例
    participant Route as Next.js API route
    participant Mock as handleMockApi
    participant Cookie as session cookie
    participant Store as Redux store
    participant Dash as /dashboard

    Browser->>Login: 填写账号密码 点登录
    Login->>API: POST /auth/login username password
    API->>Route: fetch 转发请求
    Route->>Mock: handleMockApi path=/auth/login
    Mock->>Cookie: 校验账号密码
    Cookie-->>Mock: 验证通过
    Mock-->>Route: 返回 token 和 userId
    Route-->>API: 200 + Set-Cookie yuedong_session=xxx
    API-->>Login: 登录成功响应
    Login->>Store: dispatch loadMe
    Login->>API: GET /auth/me 带 cookie
    API->>Mock: handleMockApi
    Mock->>Cookie: 从 cookie 反查用户
    Cookie-->>Mock: AuthUser
    Mock-->>API: data AuthUser
    API-->>Login: user 对象
    Login->>Store: setAuth user
    Login->>Dash: router.replace /dashboard
    Dash->>Dash: 进入 authenticated 分组 SSR 鉴权

📌 关键知识点

  1. 用户在登录页提交表单后，前端直接调用 api.post('/auth/login') — 走的是 Next.js App Router 的 API route。
  2. API route app/api/v1/...path/route.ts 内部调用 handleMockApi，它从 src/mock/handlers.ts 里找到匹配 /auth/login 的 handler。
  3. Mock 验证账号密码成功后，返回 Set-Cookie: yuedong_session=xxx，浏览器自动存储。
  4. 前端拿到 200 后再 dispatch loadMe()，会同步拉一次 /auth/me 把当前用户信息塞进 Redux store。
  5. 最后 router.replace('/dashboard') 跳仪表盘；如果 cookie 没写入或已过期，下一次进入 authenticated/layout.tsx 会被 SSR 层拦截重定向回 /login。

2 SSR 鉴权与布局渲染

带 (authenticated) 前缀的页面组，每次请求都会先在 Server 端校验登录

sequenceDiagram
    autonumber
    participant Browser as 浏览器
    participant Server as Next.js Server
    participant Layout as authenticated layout.tsx
    participant Loader as loadAuthenticatedUser
    participant Cookie as yuedong_session cookie
    participant AppShell as Provider AppShell
    participant Page as DashboardView

    Browser->>Server: GET /dashboard 或软路由跳转
    Server->>Layout: 执行共享 layout
    Layout->>Loader: loadAuthenticatedUser
    Loader->>Cookie: getSessionCookieHeader
    Cookie-->>Loader: AuthUser 或 null
    alt "cookie 存在 已登录"
        Loader-->>Layout: AuthUser 对象
        Layout->>AppShell: 注入 Redux next-themes Toast
        Layout->>Page: 渲染 Server Component
        Page->>Page: serverApiFetch 调内存 Mock
        Page-->>AppShell: 完整 DashboardView
        AppShell-->>Server: 完整 HTML
        Server-->>Browser: 200 OK + 首屏 HTML
    else "cookie 失效 未登录"
        Loader-->>Layout: null
        Layout->>Layout: redirect /login
        Layout-->>Browser: 307 Location /login
    end

📌 关键知识点

  1. Next.js App Router 中，(authenticated) 是 route group，不会产生 URL 前缀但可以用共享 layout.tsx 包裹子页面。
  2. 每次浏览器请求子页面（或点击跳转触发导航），Next.js 都会先执行共享 layout；里面调用 loadAuthenticatedUser() 读 cookie。
  3. cookie 存在 → 返回 AuthUser；layout 继续渲染 Provider(user) + AppShell + 子 Server Component。
  4. cookie 不存在或过期 → redirect('/login') 在 Server 端就完成，浏览器根本不会加载仪表盘页面。
  5. 关键代码：src/lib/api-server.ts 是 server-only 模块，只能在 Server Component / API route 里 import，它不发 HTTP 请求，直接调用内存 Mock。

3 仪表盘数据加载（CSR 补充）

Server Component 先带 initialData 做首屏；Client 组件用 useApi 拉剩余数据

sequenceDiagram
    autonumber
    participant Browser as 浏览器
    participant PageSrv as page.tsx Server
    participant View as DashboardView
    participant Hook as useApi hook
    participant Axios as api axios
    participant Mock as handleMockApi

    Browser->>PageSrv: GET /dashboard 鉴权通过
    PageSrv->>PageSrv: serverApiFetch overview
    PageSrv->>PageSrv: serverApiFetch charts
    PageSrv-->>View: 带 initialOverview initialCharts 渲染
    View-->>Browser: 首屏 HTML 已含 KPI 和图表骨架

    Browser->>View: hydration 完成 客户端挂载
    View->>Hook: useApi /metrics/overview initialOverview
    Hook->>Hook: initialData 存在 跳过首次 fetch
    Hook-->>View: 直接用 SSR 数据渲染 StatCard
    View->>Hook: useApi /metrics/charts initialCharts
    Hook->>Hook: 同样跳过首次 fetch
    Hook-->>View: Recharts 渲染 AreaChart BarChart PieChart

    Browser->>View: 改筛选条件 点查询按钮
    View->>Hook: reload
    Hook->>Axios: GET /metrics/overview regionId
    Axios->>Mock: handleMockApi
    Mock-->>Axios: data
    Axios-->>Hook: response.data
    Hook->>Hook: setData setLoading false
    Hook-->>View: data 更新
    View->>View: StatCard 和图表重渲染

📌 关键知识点

  1. Dashboard 的页面文件 app/(authenticated)/dashboard/page.tsx 是 Server Component：它调用 serverApiFetch 预取 overview 和 charts，渲染时把数据作为 props 传给 DashboardView。
  2. DashboardView 是 use client 组件。它内部的 useApi hook 会先检查 initialData !== null：有值时跳过第一次 fetch，直接用 SSR 带来的数据。
  3. 页面上的"刷新/查询"按钮触发 reload()，此时才真的 axios.get 走 HTTP → Next.js API route → Mock handler。
  4. Mock handler 返回的 JSON 会被 Recharts 直接消费（AreaChart / LineChart / PieChart）。
  5. SSR + CSR 的配合保证了：首屏 HTML 里已经包含了 KPI 数字和图表（SEO/感知快）；后续筛选/刷新走客户端异步更新（流畅）。

4 典型 CRUD：办理会员卡

Dialog 表单 → POST → Mock 写入 → Toast + 列表刷新

sequenceDiagram
    autonumber
    participant User as 用户
    participant View as MemberCardsView
    participant Dialog as Dialog 表单
    participant Axios as api axios
    participant Mock as handleMockApi
    participant DB as mock db.ts
    participant Toast as ToastProvider
    participant Hook as useApi hook

    User->>Hook: 首次进入页面 useApi GET 列表
    Hook->>Axios: GET /member-cards page=1
    Axios->>Mock: handleMockApi
    Mock->>DB: 读取 cards 数组
    DB-->>Mock: 全部会员卡
    Mock-->>Axios: data items total
    Axios-->>Hook: response.data
    Hook-->>View: data.items 渲染 Table

    User->>View: 点办理会员卡按钮
    View->>View: begin setOpen true 初始化 form
    View->>Dialog: Dialog 弹出表单

    User->>Dialog: 填完表单 点办理
    Dialog->>View: submit
    View->>Axios: POST /member-cards payload
    Axios->>Mock: handleMockApi POST /member-cards
    Mock->>Mock: 校验 payload 必填字段 手机号
    alt "校验通过"
        Mock->>DB: cards.push 新卡
        DB-->>Mock: OK
        Mock-->>Axios: 201 data newCard
        Axios-->>View: 成功
        View->>Dialog: setOpen false 关闭
        View->>Toast: toast success 绿色 Toast
        Toast-->>User: 3.5 秒后自动消失
        View->>Hook: await reload
        Hook->>Axios: GET /member-cards 同路径
        Axios->>Mock: handleMockApi
        Mock-->>Hook: 新列表
        Hook-->>View: setData Table 重渲染 新卡在最上
    else "校验失败"
        Mock-->>Axios: 400 message
        Axios-->>View: axios error
        View->>Toast: toast error 红色 Toast
        Toast-->>User: Dialog 不关 继续编辑
    end

📌 关键知识点

  1. 会员卡页面首次挂载时，useApi('/member-cards?page=1') 发 GET → 返回分页列表 → 渲染 Table。
  2. 用户点"办理会员卡" → begin() 初始化 form + setOpen(true) → Dialog 弹出表单。
  3. 点"办理"按钮 → api.post('/member-cards', payload) → Mock handler 生成新 id 并 push 到内存 db.ts → 返回新卡对象。
  4. 成功后：toast({variant:'success'}) 弹出绿色 Toast（3.5 秒自动消失）；然后 await reload() 重新 GET 拉列表 → Table 重渲染，新卡出现在第一行。
  5. 如果 Mock handler 校验失败（如手机号格式），返回 400 + message；toast 显示红色 Toast，列表不刷新，Dialog 保持打开。
